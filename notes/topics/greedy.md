# 贪心算法的具体应用

贪心算法在每一步做一个当前看起来安全的选择，并通过证明保证这个选择不会排除全局最优解。重点不是背诵“某道题应该怎么走”，而是回答：

> 为什么可以永久放弃其他选择？

## 一、判断是否适合贪心

遇到优化问题时，可以按下面的顺序思考：

1. 写出目标函数或当前状态的限制条件。
2. 找到影响结果的瓶颈，例如最短边、最早结束时间或当前可达范围。
3. 尝试证明某类选择不可能比当前选择更优。
4. 做出选择后，确认剩余问题仍然是同类型的问题。
5. 检查是否能用交换法、反证法或不变量说明全局最优解不会被删除。

贪心算法不是“每一步都选数值最大的选项”，也不是“走到局部最大值就停止”。必须存在可证明的安全选择。

## 二、盛最多水的容器：双指针排除法

题目 11 的面积为：

```text
area(left, right) = (right - left) * min(height[left], height[right])
```

若左边是短板，即 `height[left] <= height[right]`，固定左边并把右边向内移动时：

- 宽度变小；
- 高度最多仍为 `height[left]`。

因此，左边和任何更近右端点组成的容器都不可能超过当前容器，可以安全删除左边，执行 `left += 1`。右边是短板时对称处理。

这是一种“支配关系”贪心：当前短板支配了固定它时的所有更窄方案。

## 三、区间调度：优先选择最早结束的区间

给定许多可能重叠的区间，要求选择最多个互不重叠的区间时：

1. 按结束时间从小到大排序。
2. 每次选择与已选区间不冲突且结束时间最早的区间。

证明直觉：在已经选定相同数量区间的情况下，结束越早，为后面的区间留下的空间越大。若某个最优方案的第一个区间不是最早结束的区间，可以用最早结束的区间替换它，仍然可行，且不会减少后续选择。

典型题目：无重叠区间、会议室安排、活动选择。

## 四、跳跃游戏：维护最远可达位置

在数组中每个位置表示可跳跃的最大步数时，可以从左到右维护：

```text
farthest = 当前已经能够到达的最远位置
```

只要当前位置不超过 `farthest`，就用它更新新的最远位置。算法不需要枚举每条路径，因为对于后续位置来说，只要能到达某个位置，更早到达还是更晚到达没有区别；更远的可达范围支配更近的范围。

典型题目：跳跃游戏、跳跃游戏 II。

## 五、买卖股票：累加所有正收益

如果允许多次交易且每天最多持有一股，那么价格从 `price[i-1]` 上涨到 `price[i]` 时，直接累加这段正收益：

```python
if price[i] > price[i - 1]:
    profit += price[i] - price[i - 1]
```

一段连续上涨区间的总收益，等于每天上涨收益之和。因此可以把一次长交易拆成多次短交易，结果相同；所有正收益都不应被放弃。

注意：交易次数受限、包含手续费或冷冻期时，不能直接套用这个贪心，通常需要动态规划。

## 六、划分字母区间：延长到最后出现位置

遍历字符串时记录每个字符最后出现的位置。当前片段的右边界是片段内所有字符最后出现位置的最大值；当遍历位置到达这个边界时，当前片段就可以切开。

这个选择的依据是：如果片段中的某个字符在更远位置还会出现，就必须延长片段；一旦所有字符的最后出现位置都已覆盖，继续延长只会让片段变大而不会增加必要性。

## 七、最小生成树：每次加入安全的最小边

Kruskal 算法按边权从小到大考虑边：

- 如果加入该边不会形成环，就选择它；
- 如果会形成环，就跳过它。

依据是割性质：对于把当前连通分量与外部隔开的任意割，跨过该割的最小边可以安全地加入某棵最小生成树。并查集负责快速判断加入边后是否成环。

Prim 算法则从一个顶点开始，每次选择连接当前树与外部的最小边，也使用了类似的割性质。

## 八、贪心容易失败的情况

如果一个选择会影响未来的状态，而且不能证明“当前更优”会支配“当前较差”，就不能仅凭直觉使用贪心。

例如普通硬币 `1、3、4` 凑出 `6`：

- 贪心先选最大面值 `4`，剩余 `2`，需要 3 枚硬币；
- 最优方案是 `3 + 3`，只需要 2 枚。

这类问题通常需要动态规划、回溯或搜索。使用贪心前，必须先找到完整的正确性证明。

## 复习时的自检问题

- 我每一步具体选择了什么？
- 我删除了哪些候选？
- 被删除的候选为什么不可能成为更优解？
- 当前选择后，是否仍保留了最优解的可能性？
- 有没有一个最小反例能推翻我的选择？
