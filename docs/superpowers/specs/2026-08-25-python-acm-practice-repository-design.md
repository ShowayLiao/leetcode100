# Python ACM 刷题仓库设计

## 1. 目标

本仓库用于使用 Python 练习以下两类算法题：

1. LeetCode 题单，以 Hot 100 为首批内容。
2. 大厂笔试、机考和在线测评题，以标准输入和标准输出形式完成。

所有题目都以完整 ACM 程序为主要提交形式，不采用仅补全函数或 `Solution` 类的核心代码模式。

Codex 作为仓库内的 AI 判题助手和刷题教练使用：本地工具提供确定性的测试结果，Codex 在此基础上检查边界条件与复杂度，并按照使用者需要提供提示、讲解或代码审查。

## 2. 非目标

- 不实现在线判题网站。
- 不自动登录或抓取 LeetCode、牛客等平台。
- 不在项目脚本中调用 OpenAI API，不要求配置 API Key。
- 不将 AI 推理结果冒充为官方在线评测的 AC 结果。
- 不整仓复制来源项目的题面和题解。
- 首版不引入数据库、Web 前端或复杂依赖。
- 首版不维护同一道题的多份分类副本。

## 3. 设计原则

### 3.1 题目只保存一次

代码按题目来源保存。LeetCode 题目按题号保存；公司题按公司、场次日期和场次内题号保存。算法专题和题单只保存索引，避免同一道题因属于多个专题而产生重复代码。

### 3.2 ACM 模式优先

每道题的入口均为 `main.py`，通过标准输入读取数据，通过标准输出打印答案。推荐使用以下结构：

```python
import sys


def solve() -> None:
    data = sys.stdin.buffer.read().split()
    # 解析输入、求解并输出。


if __name__ == "__main__":
    solve()
```

如果一道 LeetCode 题原本依赖链表、二叉树或图节点等平台对象，必须在 `problem.md` 中定义本仓库采用的文本输入和输出协议，并在 `main.py` 中自行完成结构构造与结果序列化。

### 3.3 题面与代码分离

题目描述、来源和输入输出协议放在 `problem.md`；程序放在 `main.py`；个人复盘放在 `notes.md`；测试数据放在 `tests/`。

### 3.4 本地可验证

每道题至少保留题目样例。重要题目还应加入边界用例。测试工具以子进程方式运行 `main.py`，传入 `.in` 文件内容，并将程序标准输出与同名 `.out` 文件比较。

## 5. 命名规则

### 5.1 LeetCode

路径格式：

```text
problems/leetcode/<四位题号>_<英文短名>/
```

示例：

```text
problems/leetcode/0001_two_sum/
```

目录名使用 ASCII、小写字母和下划线，减少 Windows、Shell、编辑器和 CI 环境之间的路径兼容问题。中文题名记录在 `problem.md` 和题单中。

### 5.2 公司机考

路径格式：

```text
problems/company/<公司英文名>/<YYYY-MM-DD>/<场次题号>_<英文短名>/
```

如果题目无法确认具体日期，则使用 `undated`；如果是稳定公开题库而非具体场次，可以使用题库名，例如：

```text
problems/company/huawei/od/
```

## 6. 单题文件职责

### `problem.md`

至少记录：

- 中文题名。
- 原题或参考来源链接。
- 难度和算法标签。
- 输入描述。
- 输出描述。
- 数据范围。
- 样例说明。
- 如为 LeetCode 转 ACM 题，记录本仓库自定义的输入输出协议。

### `main.py`

- 包含完整、可独立运行的 Python 程序。
- 对外入口固定为 `solve()`。
- 不依赖 LeetCode 提供的 `Solution`、`ListNode` 或 `TreeNode` 环境。
- 默认只使用 Python 标准库。
- 不在标准输出中打印调试信息。

### `notes.md`

至少可以记录：

- 核心思路。
- 时间复杂度和空间复杂度。
- 首次错误及原因。
- 边界条件。
- 二刷日期和结果。

允许在尚未复盘时只保留标题和说明，但不保留含义不明的占位内容。

### `tests/`

每个测试由同名文件组成：

```text
01.in
01.out
```

输出比较默认忽略文件末尾多余换行，但不忽略其他空格差异，以接近真实评测环境。

## 7. 题单与专题

`sets/` 用于描述练习顺序，不存放代码副本：

- `leetcode_hot100.md`：Hot 100 进度和题目链接。
- `huawei_od.md`：华为 OD 题目索引。
- `company_interviews.md`：按公司汇总的机考索引。
- `mock_exams/`：将若干现有题目组合成限时模拟场次。

`notes/topics/` 用于总结算法套路，例如哈希、二分、动态规划和图论。专题笔记通过相对链接引用单题目录。

## 8. 模板

首版提供五种独立模板：

1. 单组输入。
2. 首行给出测试组数的多组输入。
3. 读取到文件结束的多组输入。
4. 矩阵输入。
5. 图的边集输入。

模板只展示输入输出骨架，不包含具体题目的算法答案。

## 9. 工具

### `tools/new_problem.py`

用于创建统一的单题目录。首版支持两类命令：

```text
python tools/new_problem.py leetcode 1 two_sum
python tools/new_problem.py company meituan 2026-08-18 1 problem_name
```

创建前验证参数和目标路径。目标目录已存在时拒绝覆盖，避免破坏已有答案。

### `tools/run_tests.py`

用于运行一个题目目录中的所有 `.in`/`.out` 测试：

```text
python tools/run_tests.py problems/leetcode/0001_two_sum
```

行为要求：

- 检查 `main.py` 和 `tests/` 是否存在。
- 按文件名顺序运行所有测试。
- 为每个用例显示通过或失败。
- 失败时显示预期输出、实际输出和程序错误信息。
- 使用非零退出码表示存在失败，便于以后接入 CI。
- 为单个测试设置合理的超时时间，避免死循环无限占用进程。

## 10. 错误处理

- 单题程序可以假定输入符合题目约束，不需要通用输入校验框架。
- 创建工具不得覆盖已经存在的题目目录。
- 测试工具需要区分答案错误、运行时错误和超时。
- 缺少匹配的 `.out` 文件时视为配置错误，不静默跳过。

## 11. Codex AI 判题与指导

仓库根目录使用官方支持的 `AGENTS.md` 作为 Codex 项目级指令文件，而不是 `.agents`。该文件定义 Codex 在本仓库中的默认角色、判题流程、指导方式和修改边界。文件名与作用域遵循 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

### 11.1 职责边界

本地测试工具和 Codex 的职责分离：

- `tools/run_tests.py` 负责运行代码、处理超时并进行精确输出比较。
- Codex 负责理解题意、检查算法、评估复杂度、设计边界用例和提供学习指导。
- Codex 不调用项目内的 OpenAI API 脚本；AI 能力来自当前 Codex 会话。
- 只有官方在线评测平台可以确认正式 AC。Codex 只能报告“当前本地测试通过”“发现反例”或“信息不足”。

### 11.2 默认判题流程

当使用者要求判题、检查或 review 时，Codex 应当：

1. 阅读对应的 `problem.md`、`main.py` 和现有测试。
2. 检查输入输出协议和数据范围是否明确。
3. 运行已有本地测试，不凭静态阅读直接宣布通过。
4. 检查正确性、时间复杂度、空间复杂度和 Python 特有风险。
5. 主动构造空值、极值、重复值、单元素和退化结构等边界用例。
6. 对发现的问题补充最小反例；只有在使用者要求修复时才修改答案代码。
7. 明确区分以下结论：
   - 当前本地测试通过，且静态检查未发现反例。
   - 已发现答案错误、运行时错误、超时风险或格式错误。
   - 题目约束或测试不足，暂时无法确定。

### 11.3 默认指导流程

当使用者要求提示或指导时，Codex 默认采用逐级提示：

1. 一级提示：指出可考虑的数据结构、算法方向或关键观察。
2. 二级提示：给出状态定义、循环不变量或解题步骤，但不提供完整代码。
3. 三级提示：提供伪代码或关键代码片段。
4. 完整答案：只有在使用者明确要求完整解法、直接修复或查看参考答案时提供。

指导过程中优先针对使用者当前思路提问和纠偏。除非明确要求，不覆盖 `main.py`，不把使用者的尝试替换成一份全新答案。

### 11.4 `AGENTS.md` 的核心规则

根目录 `AGENTS.md` 至少包含：

- 项目只使用 Python，题解采用完整 ACM 标准输入输出程序。
- 每道题保持 `solve()` 和 `if __name__ == "__main__"` 入口。
- 默认只使用标准库。
- 判题前必须运行测试，并检查复杂度与边界条件。
- 本地通过不等于官方 AC，结论必须附带证据和限制。
- 指导默认逐级给提示，不主动泄露完整答案。
- 仅在使用者明确要求时修改其题解代码。
- 修复问题时增加能够复现错误的回归测试。
- 新增题目时遵守统一目录、命名和来源记录规则。
- 不批量复制许可证不明确的题面或他人题解。

## 12. 首批内容

项目骨架完成后，首批只加入以下内容以验证工作流：

1. 一个完整的 LeetCode ACM 示例：`0001_two_sum`。
2. Hot 100 题单索引，不预先填充 100 份答案。
3. 五种 Python ACM 输入模板。
4. 新建题目工具和本地测试工具。
5. 输入输出笔记、错题笔记和专题目录入口。
6. 根目录 `AGENTS.md`，用于约束 Codex 的 AI 判题与指导行为。

公司真题暂不批量复制。后续从公开来源中选择题目时，只记录必要摘要和原始链接，并由使用者独立完成代码。

## 13. 验收标准

- 所有规划目录和入口文档存在。
- `0001_two_sum/main.py` 可以从标准输入读取数组与目标值，并输出两个下标。
- 示例题至少包含两个可通过的本地测试。
- `run_tests.py` 能正确报告测试通过、答案错误、运行时错误和超时。
- `new_problem.py` 能创建 LeetCode 与公司机考题目录，并拒绝覆盖现有目录。
- 根目录 `AGENTS.md` 能明确区分本地测试、AI 审查和官方 AC，并定义逐级提示规则。
- 项目不包含调用 OpenAI API 的自动判题脚本，也不要求 API Key。
- 所有 Python 文件可通过语法检查。
- README 明确说明如何新建题目、运行单题和执行测试。

## 14. 题目来源与版权边界

GitHub、LeetCode、牛客和其他网站仅作为题目发现与原始链接来源。除非内容的许可证明确允许，否则仓库不批量复制完整题面、图片或他人题解。个人目录中优先保存：

- 来源链接。
- 为理解输入输出所需的个人摘要。
- 自己编写的测试数据。
- 自己完成的代码和复盘。
